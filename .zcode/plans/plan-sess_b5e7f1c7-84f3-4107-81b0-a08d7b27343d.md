# 方案：sdkwork-api-cloud-gateway 托管 IM 实时平面（ws+tcp+udp+quic）

目标：既保持 sdkwork-im 单进程启动（现状不变），又支持由 sdkwork-api-cloud-gateway 进程托管 IM 实时平面（WebSocket upgrade + 原始 TCP/UDP/QUIC 链接监听），减少云部署进程数。已确认：全传输范围、独立 opt-in Cargo feature。

## 关键事实（探索结论）

- IM 实时平面 `services/session-gateway` 已是可嵌入库：`bootstrap_gateway_embedded_realtime_plane()`（gateway_embed.rs:120）从环境变量自举（DB/Redis/IAM pool），ws 路由 `/im/v3/api/realtime/ws` 挂在宿主 axum 路由上（lib.rs:168），TCP/UDP/QUIC 监听仅当 `SDKWORK_IM_REALTIME_TCP/UDP/QUIC_BIND_ADDR` 设置时启动（link_transport.rs），带 `shutdown(timeout)` 优雅排空。IM standalone gateway 已在用（main.rs:60-63）。
- `sdkwork_api_im_assembly::assemble_api_router_with_realtime_bootstrap(Some(&RealtimePlaneBootstrap))` 是网关侧接线点（bootstrap.rs:88-233）；不传时用内存平面兜底（ws 路由始终存在，不 404）。
- 网关现状：HTTP-only 单监听器（listener_main.rs），45 个 HTTP assembly 通过 cargo feature + component.spec.json dependencies 嵌入；`foundation-im` 已存在；dispatch 走 registry + composed router oneshot（精确路由优先），ws 路径 `/im/v3/api/realtime/ws` 被 `/im/v3/api` open 面覆盖，无需新前缀面。
- 规范现状明确禁止：APP_RUNTIME_TOPOLOGY_SPEC.md §3（"Realtime WebSocket MUST terminate on application.public-ingress"、edge 协议不得经过云网关）、APPLICATION_GATEWAY_SPEC.md §1/§5（HTTP 网关、单一 HTTP ingress）、NAMING_SPEC §4.3（edge-runtime 独立角色）。需规范修订 + ADR（ARCHITECTURE_DECISION_SPEC 强制，跨仓库拓扑变更需人工评审）。

## 一、规范修订（sdkwork-specs，breaking standards change）

1. 新 ADR：`docs/architecture/decisions/ADR-20260809-platform-gateway-realtime-hosting.md`（Status: proposed，关联/扩展 ADR-20260720-api-assembly-gateway-hosting.md；按 GOVERNANCE_SPEC 需人工评审）。
2. `APP_RUNTIME_TOPOLOGY_SPEC.md`：§3 表格与规则——云 profile 下经 ADR 批准、应用显式声明时，已部署的平台云网关可终止 application 平面的实时平面（ws upgrade + 客户端链接传输 tcp/udp/quic）；设备/edge 协议仍禁止（保留 edge-runtime 角色）。§4 表面声明增加实时托管模式字段。§6 增加托管模式声明要求。
3. `APPLICATION_GATEWAY_SPEC.md`：§1 角色表与 §4——平台云网关可托管已声明的 application 实时平面为嵌入依赖表面；§5 单一 HTTP ingress 不变（ws 升级与 HTTP 同监听器），链接监听器为显式声明的非 HTTP 监听例外。
4. `APP_RUNTIME_TOPOLOGY_NAMING.md`：注册实时环境变量族 `SDKWORK_<APP_CODE>_REALTIME_*`（BIND/URL/TLS）与网关开关 `SDKWORK_API_CLOUD_GATEWAY_REALTIME_ENABLED`；`ENVIRONMENT_SPEC.md` §4 同步。
5. `APP_RUNTIME_TOPOLOGY_ARCHETYPES.md` §3：realtime-application-platform 云策略新增 Pattern C（platform-hosted realtime）。
6. `TEST_SPEC.md`：新增网关实时托管验证行（ws upgrade 可达、链接监听仅按声明启动、单一 HTTP ingress 保持）。
7. `schemas/sdkwork.app.topology.schema.v5.json`：表面对象加可选 realtime 属性（tcp/udp/quic bind/url env、托管模式），仅增量不破坏既有枚举。
8. 工具适配（如需要）：核对 `check-single-http-ingress.mjs` / `audit-single-http-ingress-workspace.mjs` 是否误报声明的非 HTTP 链接监听，必要时扩展。

## 二、网关仓库（sdkwork-api-cloud-gateway）

1. 根 `Cargo.toml`：workspace 依赖 `session-gateway = { path = "../sdkwork-im/services/session-gateway" }`。
2. `crates/sdkwork-api-cloud-gateway/Cargo.toml`：`foundation-im-realtime = ["foundation-im", "dep:session-gateway"]`（不进 platform-foundation-suite）。
3. config crate：新增实时开关（`SDKWORK_API_CLOUD_GATEWAY_REALTIME_ENABLED` + TOML 段），默认关。
4. `embedded_dependency_routes.rs`：feature+开关+`workspace_surface_enabled("sdkwork-im")` 时——`bootstrap_gateway_embedded_realtime_plane()` 自举平面，改调 `assemble_api_router_with_realtime_bootstrap(Some(&plane.bootstrap))`，保留 `GatewayEmbeddedRealtimePlane` 句柄。
5. `runtime.rs`/`listener_main.rs`：axum 优雅停机后调用 `plane.shutdown(SDKWORK_IM_SESSION_GATEWAY_DRAIN_TIMEOUT_SECS 默认 45s)`（路由 fence + 排空）；新增异步 builder 导出 `build_sdkwork_api_cloud_gateway_router_with_embedded_realtime`（lib.rs 导出）。
6. `specs/component.spec.json`：新增 apiSurface（`/im/v3/api/realtime/ws`，routeGeneration 如 dependency-realtime-websocket-route）+ dependencies 条目 `sdkwork-im-realtime-plane`（cargoFeature foundation-im-realtime、cargoDependency session-gateway、executableExport session_gateway::bootstrap_gateway_embedded_realtime_plane、coverage 证据 id）+ routeRegistry 规则 + runtimeEntrypoints。
7. `specs/process-database-pool.spec.json`：把 IM 实时 PG pool（PostgresRealtimePool）与 Redis 客户端登记为 IM 属有的进程池（沿用 r2d2 例外模式）。
8. 测试：新增集成测试（经网关监听器 ws upgrade 可达；设 bind env 后 TCP 监听启动；停机排空）；必要时更新 verification.commands。
9. `docs/architecture/tech/TECH_ARCHITECTURE.md` 与 `etc/` 配置：更新拓扑说明、实时环境变量透传清单（node id、cluster bus、tcp/udp/quic bind、quic TLS 证书；生产 fail-closed：SDKWORK_DATABASE_URL 必须、PERMISSIVE_SCOPE_ACCESS 禁用）。

## 三、sdkwork-im 仓库（最小改动）

无需代码改动（嵌入 API 现成且为 env 驱动）。仅文档：session-gateway 说明/TECH-realtime-websocket.md 注明实时平面可由平台云网关托管；`specs/topology.spec.json` 云 profile 注释托管模式。

## 五、风险与注意

- 规范修订属 breaking standards change + 新 ADR：按 AGENTS.md/GOVERNANCE_SPEC 需人工评审（ADR 先置 proposed）。
- axum `Router::merge` 重复路由 panic：规避——IM contribution 只装配一次（默认态或实时平面态二选一），不会对同一路径装两个 handler。
- tracing 冲突：网关保持自身 tracing 初始化，绝不调用 IM 的 `init_im_service_tracing_from_env`（双重 subscriber）。
- 节点身份：网关托管时设置 `SDKWORK_IM_REALTIME_NODE_ID`（集群启用时默认值会报错）；生产缺 `SDKWORK_DATABASE_URL` 平面会 fail-closed。
- 单一 HTTP ingress 工具若误报链接监听器，属 sdkwork-specs 工具适配范围（规范修订第 8 项）。
