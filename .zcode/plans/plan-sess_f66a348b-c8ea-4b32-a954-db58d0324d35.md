## 整改内容

### 1. Dockerfile（容器配置规范修正）
- `CONFIG_FILE` 改为 `/etc/sdkwork/api-gateway/sdkwork-api-cloud-gateway.toml`（§4.5 规范路径，文件名为 `<process>.toml`）
- 镜像构建时将 config 模板拷贝到该位置（sdkwork 属主）；`/opt/sdkwork/api-gateway/config/` 保留模板副本作参考
- 新增创建 `/run/secrets/sdkwork/api-gateway`（§4.5 secret mount，chown sdkwork）
- 注释更新为指向 §4.5 表格

### 2. docker/config + compose（配置挂载）
- 新增 `docker/config/sdkwork-api-cloud-gateway.toml`：宿主可编辑的默认配置（从 production 模板演化，注释说明每个字段与 env 覆盖关系）
- `docker-compose.yml` gateway 服务增加 config 挂载：
  `./docker/config/sdkwork-api-cloud-gateway.toml:/etc/sdkwork/api-gateway/sdkwork-api-cloud-gateway.toml:ro`
- compose 注释补充 secrets 挂载说明（`./docker/secrets/` 可选注入到 `/run/secrets/sdkwork/api-gateway/`）

### 3. deployments/systemd/sdkwork-api-cloud-gateway.service（Ubuntu 安装规范）
参照 cloudrouter 模板但修正其两处规范偏差（不复制退役变量 SDKWORK_CLOUDROUTER_DEPLOYMENT_MODE、不复制非规范 config 路径）：
- `[Unit]` After=network-online.target；`[Service]` Type=simple、User=sdkwork、Group=sdkwork
- `EnvironmentFile=/etc/sdkwork/api-gateway/sdkwork-api-cloud-gateway.env`（PACKAGING_SPEC §5.5：单元不得内嵌环境赋值）
- `Environment=SDKWORK_API_CLOUD_GATEWAY_CONFIG_FILE=/etc/sdkwork/api-gateway/sdkwork-api-cloud-gateway.toml`
- `ExecStart=/usr/local/bin/sdkwork-api-cloud-gateway`、Restart=on-failure、KillSignal=SIGTERM、WantedBy=multi-user.target
- 附 `deployments/systemd/README.md` 简短说明安装步骤

### 4. docs/guides/operator/INSTALLATION_STANDARDS.md（多 OS 安装/配置规范文档）
按标准体系（引用各 spec 章节号）编写：
- **总则**：应用码 `api-gateway`；配置格式 TOML（ENVIRONMENT_SPEC §9）；优先级链（§3）
- **Linux/Ubuntu（systemd）**：§4.1 目录表、config/env/secret 文件规范（0600/0640）、sdkwork-api-cloud-gateway.service、.deb 目标矩阵（PACKAGING_SPEC §5.5）
- **Windows（SCM 服务）**：§4.4 目录表（%ProgramFiles% 只读二进制 + %ProgramData% 可变配置）、服务名 sdkwork-api-cloud-gateway
- **macOS（launchd）**：§4.3 目录表、/Library/LaunchDaemons/sdkwork.api-gateway.plist 命名
- **容器**：§4.5 目录表、config mount、/run/secrets 注入约定
- **密钥规范**：§11 Secrets Standard（/etc/sdkwork/api-gateway/*.secret、/run/secrets/sdkwork/api-gateway/<secret-name>、password_file 优先）
- **安装文件标准体系**：INSTALL.md + install-manifest.json（installConfiguration）+ checksums.sha256 + config 模板 + specs/ 的必须性（PACKAGING_SPEC §3、DEPLOYMENT_SPEC §5.4）
- **环境变量前缀迁移说明**：SDKWORK_API_CLOUD_GATEWAY_* 按 ENVIRONMENT_SPEC §4 作为 legacy 前缀文档化保留

### 5. scripts/package-server.mjs（安装文件标准体系增强）
- `createInstallManifest` 增加 `installConfiguration` 字段：声明 host 目录映射（config → /etc/sdkwork/api-gateway/、data → /var/lib/sdkwork/api-gateway/、logs → /var/log/sdkwork/api-gateway/、cache → /var/cache/sdkwork/api-gateway/、run → /run/sdkwork/api-gateway/）与 systemd 单元名（PACKAGING_SPEC §3/§5.5）
- `renderInstallGuide` 增加"生产部署（systemd）"章节，指向 INSTALLATION_STANDARDS.md

### 6. 文档更新 + 验证
- DOCKER_STANDALONE_QUICK_DEPLOY.md「配置说明」章节：更新为 /etc/sdkwork/api-gateway/ + TOML/env 分层 + secrets 挂载说明
- 验证：`pnpm build:container` 重建镜像 → `docker compose up -d` → 三域名 /healthz、/readyz 200 → 容器内核对 /etc/sdkwork/api-gateway/sdkwork-api-cloud-gateway.toml 生效、/run/secrets/sdkwork/api-gateway 存在 → `pnpm check` 不回归
