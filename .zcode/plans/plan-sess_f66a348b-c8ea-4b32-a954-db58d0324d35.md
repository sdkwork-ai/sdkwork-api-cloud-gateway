# SDKWork API Cloud Gateway — Standalone Docker 打包与 WSL 快速部署

## 背景事实（已探明）
- WSL Ubuntu-22.04 运行中：docker 29.3.0、nginx 1.18（80/443）、node 22 + pnpm 10.33、cargo 1.97
- cloudrouter 容器组合已在 3903→3900 运行（compose 目录 /mnt/e/sdkwork-space/sdkwork-cloudrouter）
- gateway 配置：production TOML + env 覆盖（ALLOWED_HOSTS/CORS 覆盖为 testapidocker 域名；SDKWORK_DATABASE_* 注入 DB；46 个 database-modules 需 SDKWORK_*_APP_ROOT env，含 5 个特例 key）
- 打包规范：PNPM_SCRIPT_SPEC 禁止 `docker:*` → 用 `build:container`；APP_MANIFEST_SPEC 支持 CONTAINER_IMAGE/DOCKER_IMAGE 条目；RUNTIME_DIRECTORY_SPEC §4.5 容器布局
- Windows hosts 可经 WSL 直接写入；有一行过时 `testimdocker.*` 残留需清理

## 端口规划（按用户要求 391x 段）
- 容器内监听 3900（spec 默认应用公共入口），主机映射 **3910→3900**
- 391x 段为 gateway docker 部署保留段（3910 gateway 容器；3911+ 预留）；部署前校验 WSL `ss -tln` 与 Windows `Get-NetTCPConnection` 确认 3910 空闲，被占用则顺延 3911/3912
- nginx 在 WSL 内代理 `127.0.0.1:3910`

## 仓库内交付物
1. **Dockerfile**（根目录）：debian:bookworm-slim；仅装 libssl3/ca-certificates/curl（去掉 cloudrouter 的 gnupg+postgresql-client → 镜像更小）；sdkwork 非 root 用户；§4.5 目录布局（/etc/sdkwork/api-gateway、/var/lib/sdkwork/api-gateway 等）；46 个 SDKWORK_*_APP_ROOT + SDKWORK_APP_ROOT + SDKWORK_DATABASE_MODULES_ROOT ENV；LABEL；EXPOSE 3900；ENTRYPOINT container/entrypoint
2. **container/entrypoint**：最小 sh，设置 deployment profile / runtime target env 后 exec 二进制
3. **docker-compose.yml**（根目录）：postgres:16-alpine（无主机端口，schema init 挂载）+ sdkwork-api-cloud-gateway:local；**3910→3900**；env 注入 CORS/hosts/database/app-roots；/readyz 健康检查（start_period 240s 覆盖 46 模块迁移）；资源限额（env 可调）；命名卷；不含 redis（gateway 限流为进程内桶，无共享状态需求）
4. **docker/.env.example**：DB 凭据/CORS/资源/日志可配置项（含 GATEWAY_HOST_PORT=3910）
5. **docker/postgres/init/001-create-schema.sql**：CREATE SCHEMA sdkwork_api_gateway + GRANT
6. **docker/nginx/testapidocker-api-gateway.conf**：三个域名 → proxy_pass http://127.0.0.1:3910（透传真实 Host + X-Forwarded-*）
7. **scripts/build-api-cloud-gateway-container.mjs**：组装 dist/container-image-build 构建上下文（复用 package-server.mjs 导出的 database host 解析与路径工具），docker build → sdkwork-api-cloud-gateway:local，写 dist/container-image.json（版本/摘要/镜像大小），支持 --check/--dry-run/--json/--skip-build/--tag/--force
8. **package.json**：新增 `build:container`、`build:container:check`（符合 PNPM_SCRIPT_SPEC）
9. **sdkwork.app.config.json**：新增容器包条目 linux-x64-standalone-container-oci（sourceType CONTAINER_IMAGE / packageFormat DOCKER_IMAGE / runtimeTarget container）
10. **docs/deploy/docker-standalone.md**：快速部署文档（构建→部署→nginx→hosts→验证）

## WSL 部署执行步骤
1. 校验 3910 端口空闲（WSL + Windows 两侧）
2. WSL 中构建 linux release 二进制：cargo build --release（--no-default-features --features platform-foundation-suite，CARGO_TARGET_DIR=/home/sdkwork/api-gateway-release-target 走 ext4，后台运行，预计耗时较长）
3. 运行 `pnpm build:container` 构建镜像（报告镜像大小）
4. `docker compose up -d` 并等待健康
5. nginx：安装 sites-enabled 配置 + `nginx -t` + reload
6. Windows hosts：清理 testimdocker 残留行，追加 `127.0.0.1 testapidocker.sdkwork.com testapidocker.birdcoder.com testapidocker.dtupay.com`
7. 验证：Windows 端 curl 三个域名 /healthz 与 /readyz；容器日志与镜像大小报告

## 质量与合规
- 完成后运行 `pnpm check:standards`、`pnpm workflow:validate` 等确保不回归
- 镜像大小控制：去掉 gnupg/postgresql-client，仅保留运行必需运行时依赖
- 打包产物全部落在 dist/（已被 gitignore）
- 范围说明：不修改 sdkwork.workflow.json（CI 容器目标留作后续）；不做仓库外改动
