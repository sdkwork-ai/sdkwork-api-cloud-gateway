### 3.1 Incident: sdkwork-payment migration checksum mismatch (fixed)

The first demo boot after the image load crash-looped (RestartCount 51) with:

```
failed to bootstrap database module `payment` from `sdkwork-payment`:
migration error: checksum_mismatch for migration 0002:
applied=0ad0c442..., current=bbe634de...
```

Diagnosis: `sdkwork-payment` commit `8d31827` (already included in the 0.1.22 wave) changed
`0002_payment_no_uniqueness.up.sql` / `0003_payment_attempt_provider_code.up.sql` by **rollback
metadata comments only** - the applied DDL is identical. Production's
`ops_schema_migration_history` had already been reconciled to the current file hashes during the
0.1.22 wave; the demo database still carried the pre-reconciliation hashes because it was
provisioned earlier in the day.

Remedy (same as production, evidence-based):

```sql
update ops_schema_migration_history set checksum='bbe634de12a59abe8d86b43c25b3355826232b8423ae749be0c8d0eb355401df'
  where module_id='payment' and version='0002' and engine='postgres';
update ops_schema_migration_history set checksum='856c5496f9ccfc7e0b5233c126a9a67d1b6f3fc394eb8a88b085eeccc97a39ad'
  where module_id='payment' and version='0003' and engine='postgres';
```

The production database carries exactly these two hashes for the same rows, confirming the
reconciliation values. The gateway restarted and passed the migration gate; the deploy health gate
then reported `gateway is healthy (waited 615s)`.

## 5. Public edge and DNS

The host nginx already serves the demo family from
`/etc/nginx/sites-available/sdkwork/sdkwork-api-cloud-gateway-demo.conf` (enabled):

- `upstream sdkwork_api_gateway_demo { server 127.0.0.1:3914; keepalive 32; }`
- `server_name` covers `api-demo.sdkwork.com`, `api-demo.birdcoder.com` and the other 14
  `api-demo.*` base-domain hosts; HTTP 80 (with ACME webroot) and HTTPS 443 (`http2 on`, TLS
  1.2/1.3, self-signed multi-SAN certificate `/etc/sdkwork/certs/cloudrouter-demo/`), with
  `Host`, `X-Real-IP`, `X-Forwarded-For/Proto/Host/Port`, Upgrade/Connection and the same
  timeouts as the `api.birdcoder.com` server block; `nginx -t` passes.
- Verified through the edge: `Host: api-demo.sdkwork.com` and `Host: api-demo.birdcoder.com` ->
  200 on both :80 and :443 (`-k`).

**Open external prerequisite: DNS.** `api-demo.birdcoder.com` and `api-demo.sdkwork.com` are still
`NXDOMAIN` at both authoritative DNS (DNSPod) and public resolvers; the domains are not wildcard
resolved, and the host has no DNS provider credentials or certbot DNS plugin, so the records cannot
be created from here. Required records:

```
api-demo.birdcoder.com   A   49.233.93.219
api-demo.sdkwork.com     A   49.233.93.219
```

After DNS is in place a trusted certificate can be issued and swapped in:

```sh
sudo certbot certonly --webroot -w /var/www/html \
  -d api-demo.birdcoder.com -d api-demo.sdkwork.com
# then point the demo 443 block at /etc/letsencrypt/live/<name>/{fullchain,privkey}.pem
```
